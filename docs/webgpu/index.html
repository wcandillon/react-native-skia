WebGPU

React Native Skia renders with Graphite, which runs on Dawn, Google's WebGPU implementation. React Native Skia does not expose a WebGPU API itself. To use WebGPU in your app, install React Native WebGPU alongside it.

When both packages are installed, they share a single copy of Dawn, and the GPU device Skia renders with becomes a regular WebGPU GPUDevice. Textures created on that device can be used by both libraries without any copy:

  • From WebGPU to Skia: draw the output of a WebGPU pipeline or of a three.js scene in a Skia canvas, and compose it with anything Skia can draw.
  • From Skia to WebGPU: draw text, paths, or any Skia drawing straight into a texture that a WebGPU pipeline samples.
  • Camera and video frames: draw the frames that React Native WebGPU decodes or wraps in a Skia canvas.
  • View snapshots: draw a snapshot of any React Native view, taken by React Native WebGPU, in a Skia canvas.
info

The interop APIs on this page are only available on native platforms. On the Web, Skia runs on WebGL through CanvasKit.

The GPU device​

Skia.gpu describes the GPU device Skia renders with: Vulkan on Android, Metal on iOS, WebGL on the web.

import { Skia } from "react-native-skia";

const { isAvailable, backend, device, description, error } = Skia.gpu;
PropertyDescription
isAvailableWhether Skia can render on this device, right now
backend"Vulkan", "Metal" or "WebGL"; empty when unavailable
vendor, architecture, device, descriptionThe adapter, in the terms of WebGPU's GPUAdapterInfo (native only)
errorWhy the GPU is unavailable; null when it is
lostThe promise of the loss of the device, see device loss
foregroundWhether the app is in the foreground and active, where GPU work runs, see background and foreground

Availability​

On a device without a GPU Skia can render with (on Android, one without Vulkan 1.1, see the Vulkan section of the installation guide), the app still runs. Skia.gpu.isAvailable is false and Skia.gpu.error says why: every canvas stays blank, CPU work (paths, decoding, raster images) still runs, and the APIs that need the GPU (offscreen surfaces, snapshots, texture images) throw an error with the same message.

Background and foreground​

iOS refuses GPU work from an app in the background, and refused work used to lose the device. React Native Skia now holds the GPU work submitted while the app is in the background and runs it when the app comes back: nothing is lost and nothing is refused. The same applies to the device Skia.getNativeDevice() shares with React Native WebGPU. Canvases present nothing meanwhile and catch up on return.

Holding is not free: every frame drawn in the background keeps what it uses in memory until the return. A frame callback or a video player that keeps drawing while the app is in the background should stop instead. Skia.gpu.foreground is false from the moment the app starts to resign active (a lock, a swipe home, an incoming call) until it is active again. It can be read synchronously on every runtime, a worklet included, and it flips before any AppState event reaches JS.

import { Skia } from "react-native-skia";
import { useFrameCallback } from "react-native-reanimated";

const surface = Skia.Surface.MakeOffscreen(256, 256)!;

useFrameCallback(() => {
  "worklet";
  if (!Skia.gpu.foreground) {
    // Nothing to show: skip the frame rather than queue it.
    return;
  }
  surface.getCanvas().drawColor(Skia.Color("cyan"));
  surface.flush();
});

Held work does not finish until the app comes back, so surface.flush(true), which waits for the GPU, blocks its thread until then. Check Skia.gpu.foreground before calling it.

On Android, Skia.gpu.foreground is whether the host activity is resumed; on the web, whether the document is visible.

Device loss​

The device can be lost while the app runs: a driver reset, or the GPU out of memory. React Native Skia then replaces it with a new device, and canvases render again on their own. Everything made on the lost device is gone for good, though safe to use (it draws nothing): offscreen surfaces and the images taken from them, texture images, snapshots of views, and the device Skia.getNativeDevice() returned.

Skia.gpu.lost is the promise of the loss of the device in use, like WebGPU's GPUDevice.lost. It resolves once React Native Skia has replaced the device; Skia.gpu then describes the new device, with a lost promise of its own for the next loss.

import { Skia } from "react-native-skia";

Skia.gpu.lost.then(({ reason, message }) => {
  console.log(`GPU device lost (${reason}): ${message}`);
  // Skia.gpu now describes the new device: make your GPU objects again.
});

Skia.gpu.isAvailable is false between the loss and the replacement, and stays false, with Skia.gpu.error saying why, if no replacement could be made.

In React, useGpu() returns Skia.gpu as state and renders the component again once a lost device has been replaced: make your GPU objects with its value as a dependency and they are made again too.

import { useMemo } from "react";
import { Canvas, Image, Skia, useGpu } from "react-native-skia";

const Demo = () => {
  const gpu = useGpu();
  // Made again on the new device after a loss.
  const image = useMemo(() => {
    const surface = Skia.Surface.MakeOffscreen(256, 256)!;
    surface.getCanvas().drawColor(Skia.Color("cyan"));
    surface.flush();
    return surface.makeImageSnapshot();
  }, [gpu]);
  return (
    <Canvas style={{ flex: 1 }}>
      <Image image={image} x={0} y={0} width={256} height={256} />
    </Canvas>
  );
};

Code sharing the device with React Native WebGPU imports it again the same way, see sharing the device.

Pipeline compilation​

The GPU compiles a pipeline for each kind of drawing the first time a canvas calls for it: a solid rounded rectangle, an image, a gradient-filled path, a line of text. A compile takes from a few milliseconds to a few hundred on a fresh install, and the frame that needs the pipeline waits for it, so a screen that introduces several at once comes up late the first time it appears. React Native Skia compiles these pipelines ahead of the frames, on a thread of its own, while the frames leave the GPU alone. On a launch without a record, it compiles a built-in set: solid colors, images and gradients on every shape, text, and drop shadows. From then on, it records the pipelines the app actually uses in its cache directory (rnskia/pipelines.bin) and compiles those at the next launch, so the screens the app showed come up without a compile on the frame. A pipeline the record does not cover is compiled when first needed, as before, and recorded. A pipeline whose paint uses a runtime effect, one of Skia's own (a blur, a morphology, the luma color filter) or one of yours, is compiled when first needed too, but not recorded: Graphite can only compile it on the context that drew it. The compiled shaders themselves, and on Android the driver's pipeline cache, are kept in the same directory by Dawn's blob cache: the one React Native WebGPU keeps for the devices it creates (see its pipeline cache), here for Skia's device, so a later launch mostly reads them back. Both are caches: clearing the app's cache directory costs the next launch a built-in set and the compiles, and a React Native Skia update that changes what Graphite or Dawn read starts them over. The log reports what each launch compiled ahead of the frames.

Sharing the device​

Install React Native WebGPU next to React Native Skia, and follow its installation instructions for the rest of the setup:

yarn add react-native-webgpu

Pick the versions of the two packages from one row of this table; the React Native WebGPU documentation keeps the reference copy of it.

3.9.0 to 3.9.20.20.0 to 0.21.2
3.7.0 to 3.8.10.17.0 to 0.19.2

From react-native-skia 3.1.0 and react-native-webgpu 0.13.0, both packages depend on the same react-native-webgpu-dawn package, which ships the Dawn build they link, so that only one copy of Dawn exists in the app. The native build verifies that the two resolve the same version of it and fails with a Dawn version mismatch error otherwise: upgrade react-native-skia and react-native-webgpu together. The mixed rows work because the older release vendors the same Dawn commit (react-native-skia 3.1.0 accepts a react-native-webgpu 0.12.1 whose dawnCommit matches, and react-native-skia 3.0.8 defers to react-native-webgpu's Dawn). On Android, react-native-skia 3.0.6 and 3.0.7 cannot pair with react-native-webgpu 0.13.0 and later: they still package their own libwebgpu_dawn.so next to the one from the package and the build fails merging the two.

Once installed, the device Skia renders with is yours to use from WebGPU. Skia.getNativeDevice() returns a pointer to it, and importDevice() from React Native WebGPU wraps it into a GPUDevice:

import { Skia } from "react-native-skia";
import { importDevice } from "react-native-webgpu";

const device = importDevice(Skia.getNativeDevice());

Everything you create with this device (textures, buffers, pipelines) lives on the same device as Skia's own resources, which is what makes sharing textures possible. A few things to know about it:

  • The device is owned by Skia, which keeps it alive for as long as it renders with it.
  • The device can be lost: a driver reset, or the GPU out of memory. Skia then replaces it with a new device (see device loss). The imported GPUDevice does not learn of the loss (its lost promise never settles) and everything created on it is gone: import the new device and create your resources again, with useGpu() in React or Skia.gpu.lost elsewhere.
  • navigator.gpu.requestAdapter() and requestDevice() still work as usual. Use a device of your own when you want your GPU work isolated from Skia's command queue, but keep in mind that a texture created on another device cannot be shared with Skia.
import { useMemo } from "react";
import { Skia, useGpu } from "react-native-skia";
import { importDevice } from "react-native-webgpu";

// A texture on Skia's device. Once a lost device has been replaced, the new
// one is imported and the texture created again on it.
const useSharedTexture = () => {
  const gpu = useGpu();
  return useMemo(() => {
    const device = importDevice(Skia.getNativeDevice());
    return device.createTexture({
      size: [256, 256],
      format: "rgba8unorm",
      usage:
        GPUTextureUsage.RENDER_ATTACHMENT | GPUTextureUsage.TEXTURE_BINDING,
    });
  }, [gpu]);
};

The shared device works like any other device, for instance to configure a WebGPU canvas:

import { Skia } from "react-native-skia";
import type { CanvasRef } from "react-native-webgpu";
import { importDevice } from "react-native-webgpu";

const configure = (canvas: CanvasRef) => {
  const device = importDevice(Skia.getNativeDevice());
  const context = canvas.getContext("webgpu")!;
  context.configure({
    device,
    format: navigator.gpu.getPreferredCanvasFormat(),
    alphaMode: "opaque",
  });
  return { device, context };
};

The interop surface is small:

APIDirectionDescription
Skia.getNativeDevice()Pointer to Skia's device, for importDevice()
Skia.Image.MakeFromGPUTexture(texture)WebGPU to SkiaWraps a GPUTexture into an SkImage, without copy
Skia.Surface.MakeFromGPUTexture(texture)Skia to WebGPUCreates an SkSurface that draws into a GPUTexture, without copy
Skia.Image.MakeGPUTextureFromImage(image)Skia to WebGPUDraws an SkImage into a new texture, for adoptTexture()

The two functions that take a texture read its nativePointer, an extension of GPUTexture provided by React Native WebGPU. MakeGPUTextureFromImage() returns such a pointer, which adoptTexture() turns into a GPUTexture: only React Native WebGPU can build the typed object, the same way importDevice() builds the GPUDevice. A raw WGPUTexture pointer (a BigInt) is accepted wherever a texture is, for libraries that export textures without React Native WebGPU. Camera and video frames and view snapshots go through a texture as well.

From WebGPU to Skia​

Skia.Image.MakeFromGPUTexture() wraps a WebGPU texture into an SkImage. The image references the texture, so wrapping it is free. The texture must be created on the shared device with the TEXTURE_BINDING usage.

In the example below, a WebGPU pipeline renders a triangle into a texture, and a Skia canvas draws that texture.

import React, { useEffect } from "react";
import { PixelRatio } from "react-native";
import { useSharedValue } from "react-native-reanimated";
import type { SkImage } from "react-native-skia";
import { Canvas, Image, Skia, useCanvasSize } from "react-native-skia";
import { importDevice } from "react-native-webgpu";

const shader = /* wgsl */ `
@vertex
fn vs_main(@builtin(vertex_index) vertexIndex: u32) -> @builtin(position) vec4f {
  var pos = array<vec2f, 3>(
    vec2f( 0.0,  0.5),
    vec2f(-0.5, -0.5),
    vec2f( 0.5, -0.5)
  );
  return vec4f(pos[vertexIndex], 0.0, 1.0);
}

@fragment
fn fs_main() -> @location(0) vec4f {
  return vec4f(1.0, 0.5, 0.2, 1.0);
}
`;

export const TriangleInSkia = () => {
  const { size, onLayout } = useCanvasSize();
  const image = useSharedValue<SkImage | null>(null);

  useEffect(() => {
    const width = Math.floor(size.width * PixelRatio.get());
    const height = Math.floor(size.height * PixelRatio.get());
    if (width === 0 || height === 0) {
      return;
    }
    // 1. A GPUDevice backed by Skia's device
    const device = importDevice(Skia.getNativeDevice());

    // 2. A texture on that device: WebGPU renders to it, Skia samples it
    const format = navigator.gpu.getPreferredCanvasFormat();
    const texture = device.createTexture({
      size: [width, height],
      format,
      usage:
        GPUTextureUsage.RENDER_ATTACHMENT | GPUTextureUsage.TEXTURE_BINDING,
    });

    // 3. Render with WebGPU
    const module = device.createShaderModule({ code: shader });
    const pipeline = device.createRenderPipeline({
      layout: "auto",
      vertex: { module, entryPoint: "vs_main" },
      fragment: { module, entryPoint: "fs_main", targets: [{ format }] },
    });
    const encoder = device.createCommandEncoder();
    const pass = encoder.beginRenderPass({
      colorAttachments: [
        {
          view: texture.createView(),
          clearValue: { r: 0.1, g: 0.1, b: 0.1, a: 1 },
          loadOp: "clear",
          storeOp: "store",
        },
      ],
    });
    pass.setPipeline(pipeline);
    pass.draw(3);
    pass.end();
    device.queue.submit([encoder.finish()]);

    // 4. Wrap the texture into an SkImage, without any copy
    image.value = Skia.Image.MakeFromGPUTexture(texture);

    return () => {
      // Drop the image before the texture it samples
      const last = image.value;
      image.value = null;
      last?.dispose();
      texture.destroy();
    };
  }, [size.width, size.height, image]);

  return (
    <Canvas onLayout={onLayout} style={{ flex: 1 }}>
      <Image
        image={image}
        x={0}
        y={0}
        width={size.width}
        height={size.height}
        fit="fill"
      />
    </Canvas>
  );
};

The result is a regular Skia image: you can use it in an Image, an ImageShader, or as the input of an image filter.

To animate, render to the same texture on every frame and assign a new SkImage to the shared value. The new object is what makes the canvas redraw:

const render = () => {
  // ...encode and submit the WebGPU commands for this frame
  const previous = image.value;
  image.value = Skia.Image.MakeFromGPUTexture(texture);
  previous?.dispose();
  frame = requestAnimationFrame(render);
};

From Skia to WebGPU​

Drawing into a texture​

Skia.Surface.MakeFromGPUTexture() creates a surface that draws directly into a WebGPU texture. Create the texture on the shared device with the RENDER_ATTACHMENT usage, and add TEXTURE_BINDING to sample the result from WebGPU.

import { Skia } from "react-native-skia";
import { importDevice } from "react-native-webgpu";

const width = 1024;
const height = 1024;
const device = importDevice(Skia.getNativeDevice());
const texture = device.createTexture({
  size: [width, height],
  format: navigator.gpu.getPreferredCanvasFormat(),
  usage: GPUTextureUsage.RENDER_ATTACHMENT | GPUTextureUsage.TEXTURE_BINDING,
});

// Wrap the texture once
const surface = Skia.Surface.MakeFromGPUTexture(texture);
const canvas = surface.getCanvas();
const paint = Skia.Paint();
paint.setColor(Skia.Color("cyan"));

// Draw as often as needed, for instance on every frame
const draw = () => {
  canvas.clear(Skia.Color("black"));
  canvas.drawCircle(width / 2, height / 2, 100, paint);
  // Submits Skia's commands on the shared queue,
  // ahead of the WebGPU commands that will sample the texture
  surface.flush();
};

Call surface.flush() after drawing and before the WebGPU pass that samples the texture. When you are done, dispose the surface before destroying the texture:

surface.dispose();
texture.destroy();

Exporting an image​

Skia.Image.MakeGPUTextureFromImage() turns any SkImage into a WebGPU texture. It creates a new texture on the shared device and draws the image into it once. The returned pointer must be adopted exactly once with adoptTexture(), which owns the texture from then on.

import type { SkImage } from "react-native-skia";
import { Skia } from "react-native-skia";
import { adoptTexture } from "react-native-webgpu";

const toTexture = (image: SkImage): GPUTexture =>
  adoptTexture(Skia.Image.MakeGPUTextureFromImage(image));

Native buffers​

Camera and video frames live in native buffers: an IOSurface (usually wrapped in a CVPixelBuffer) on Apple platforms, an AHardwareBuffer on Android. Skia does not import them. React Native WebGPU owns these buffers: it decodes videos into them, wraps the buffers that other libraries produce, ties their lifetime to a NativeVideoFrame object, and renders a frame into a texture of the shared device with queue.copyExternalImageToTexture(), converting YUV to RGB and applying the rotation of the video or the camera on the GPU. Skia.Image.MakeFromGPUTexture() then wraps that texture, like any WebGPU texture. There is one path on both platforms, whatever the format of the frame. It needs React Native WebGPU 0.11.1 or above.

Playing a video​

createVideoPlayer() from React Native WebGPU decodes a video into native buffers, with the playback controls of an HTMLMediaElement (play(), pause(), currentTime, loop, volume). copyLatestFrame() returns the most recently decoded frame, or null when no new frame was decoded since the last call. Copy each new frame into a texture, wrap the texture into an image, and publish the image through a shared value:

import React, { useEffect } from "react";
import { useSharedValue } from "react-native-reanimated";
import type { SkImage } from "react-native-skia";
import { Canvas, Image, Skia, useCanvasSize } from "react-native-skia";
import { createVideoPlayer, importDevice } from "react-native-webgpu";

export const Video = ({ url }: { url: string }) => {
  const { size, onLayout } = useCanvasSize();
  const image = useSharedValue<SkImage | null>(null);

  useEffect(() => {
    const device = importDevice(Skia.getNativeDevice());
    const player = createVideoPlayer(url);
    let texture: GPUTexture | null = null;
    let raf = 0;
    const render = () => {
      const frame = player.copyLatestFrame();
      if (frame) {
        // The frame is upright once rotated; a 90 or 270 degree rotation
        // swaps its width and height
        const rotated = player.rotation === 90 || player.rotation === 270;
        const width = rotated ? frame.height : frame.width;
        const height = rotated ? frame.width : frame.height;
        if (!texture || texture.width !== width || texture.height !== height) {
          const previous = image.value;
          image.value = null;
          previous?.dispose();
          texture?.destroy();
          texture = device.createTexture({
            size: [width, height],
            format: navigator.gpu.getPreferredCanvasFormat(),
            usage:
              GPUTextureUsage.RENDER_ATTACHMENT |
              GPUTextureUsage.TEXTURE_BINDING,
          });
        }
        // Convert and rotate the frame into the texture on the GPU
        device.queue.copyExternalImageToTexture(
          { source: frame, rotation: player.rotation },
          { texture },
          [width, height]
        );
        frame.release();
        // A new image is what makes the canvas redraw
        const previous = image.value;
        image.value = Skia.Image.MakeFromGPUTexture(texture);
        previous?.dispose();
      }
      raf = requestAnimationFrame(render);
    };
    player.play();
    raf = requestAnimationFrame(render);
    return () => {
      cancelAnimationFrame(raf);
      player.release();
      const last = image.value;
      image.value = null;
      last?.dispose();
      texture?.destroy();
    };
  }, [url, image]);

  return (
    <Canvas onLayout={onLayout} style={{ flex: 1 }}>
      <Image
        image={image}
        x={0}
        y={0}
        width={size.width}
        height={size.height}
        fit="cover"
      />
    </Canvas>
  );
};

The result is a regular Skia image: use it in an Image, an ImageShader, or as the input of an image filter. The copy and the Skia drawing are submitted on the same queue, in order, so the image is complete by the time Skia samples it.

Camera frames​

A camera library that exposes its frames as native buffers works the same way. createVideoFrameFromNativeBuffer(pointer) from React Native WebGPU wraps the CVPixelBufferRef or AHardwareBuffer* the library hands out (for instance VisionCamera's frame.getNativeBuffer().pointer) into a NativeVideoFrame, which copyExternalImageToTexture() then renders into a texture. Pass the frame's orientation as rotation and mirrored, and release the frame once the copy is issued.

Lifetime​

  • Release frames early. The texture holds the pixels once the copy is issued: release the frame right after, so the video player or the camera gets its buffer back.
  • Reuse the texture. Create a new one only when the frame size changes, and dispose the images that sample it before destroying it.
  • Any runtime. Like every GPU-backed image, the result can be created on one runtime and drawn by any canvas or worklet runtime.

On the Web, where Skia runs on CanvasKit, Skia.Image.MakeFromNativeBuffer() creates an image from a CanvasImageSource instead: a <video> element, an ImageBitmap, or a canvas.

View snapshots​

A snapshot of a React Native view follows the same path as a video frame: React Native WebGPU rasterizes the view into a texture of the shared device with queue.drawElementImageToTexture(), and Skia.Image.MakeFromGPUTexture() wraps that texture into an image. Skia has no view snapshot API of its own: makeImageFromView() from v2 was removed in favor of this path. It needs React Native WebGPU 0.14.0 or above.

The view is rendered by the platform, so the snapshot includes everything the screen shows: text, images, SVGs, transforms, elevation shadows, and Skia canvases. On iOS and on Android 13 and above, the view is drawn into the texture on the GPU, without any copy through the CPU. Pass the view as a ref, a host instance, or a tag from findNodeHandle(); render it with collapsable={false} so that React Native does not optimize the host view away.

import React, { useCallback, useRef } from "react";
import type { LayoutChangeEvent } from "react-native";
import { Button, PixelRatio, Text, View } from "react-native";
import { useSharedValue } from "react-native-reanimated";
import type { SkImage } from "react-native-skia";
import { Canvas, Image, Skia } from "react-native-skia";
import { importDevice } from "react-native-webgpu";

export const Snapshot = () => {
  const ref = useRef<View>(null);
  const layout = useRef({ width: 0, height: 0 });
  const onLayout = useCallback((event: LayoutChangeEvent) => {
    layout.current = event.nativeEvent.layout;
  }, []);
  const image = useSharedValue<SkImage | null>(null);
  const texture = useRef<GPUTexture | null>(null);

  const takeSnapshot = useCallback(async () => {
    const { width, height } = layout.current;
    if (width === 0 || height === 0) {
      return;
    }
    const device = importDevice(Skia.getNativeDevice());
    // The natural size of the snapshot: the view's size in points times the
    // pixel ratio
    const scale = PixelRatio.get();
    const next = device.createTexture({
      size: [Math.round(width * scale), Math.round(height * scale)],
      format: "rgba8unorm",
      usage:
        GPUTextureUsage.COPY_DST |
        GPUTextureUsage.RENDER_ATTACHMENT |
        GPUTextureUsage.TEXTURE_BINDING,
    });
    // The view is rasterized on the UI thread, hence the promise.
    // Skia images are premultiplied: ask for premultiplied pixels.
    await device.queue.drawElementImageToTexture(
      { source: ref },
      { texture: next, premultipliedAlpha: true }
    );
    // Wrap the texture, without any copy. A new image is what makes the
    // canvas redraw; the previous one is dropped before its texture.
    const previous = image.value;
    image.value = Skia.Image.MakeFromGPUTexture(next);
    previous?.dispose();
    texture.current?.destroy();
    texture.current = next;
  }, [image]);

  return (
    <View style={{ flex: 1 }}>
      <View
        ref={ref}
        onLayout={onLayout}
        collapsable={false}
        style={{ flex: 1, backgroundColor: "cyan" }}
      >
        <Text>This is a React Native view</Text>
      </View>
      <Button title="Take snapshot" onPress={takeSnapshot} />
      <Canvas style={{ flex: 1 }}>
        <Image image={image} x={0} y={0} width={256} height={256} fit="contain" />
      </Canvas>
    </View>
  );
};

The result is a regular GPU image: use it in an Image, an ImageShader, or as the input of an image filter, from any canvas and any thread. The texture must be created with COPY_DST; RENDER_ATTACHMENT lets React Native WebGPU draw the view into it on the GPU (without it, the pixels are read back through the CPU), and TEXTURE_BINDING lets Skia sample it. drawElementImageToTexture() also takes a source rectangle, a destination size and origin, and works from a worklet runtime: see its documentation for the details, and for what each platform includes in a snapshot.

On Android, a SurfaceView is composed outside the view hierarchy and comes out blank in a snapshot. A Skia Canvas is backed by a TextureView unless its android.backingView asks for a SurfaceView: keep the default for a canvas that must appear in snapshots (the same applies to a React Native WebGPU Canvas).

On the Web, rasterize the DOM node into a canvas (for instance with html2canvas) and pass the canvas to Skia.Image.MakeFromNativeBuffer().

Three.js​

Three.js runs on React Native WebGPU through its WebGPURenderer. The three.js guide of React Native WebGPU covers the project setup (Metro, Babel, polyfills, and asset loading).

Pass the shared device to the renderer, and three.js and Skia can exchange textures in both directions:

import * as THREE from "three/webgpu";
import { Skia } from "react-native-skia";

const makeRenderer = (context: GPUCanvasContext) =>
  new THREE.WebGPURenderer({
    antialias: true,
    canvas: context.canvas,
    context,
    // three.js renders on Skia's device instead of requesting its own
    device: importDevice(Skia.getNativeDevice()),
  });

A Skia drawing as a three.js texture​

Wrap the texture Skia draws into (see drawing into a texture) in a THREE.ExternalTexture:

import * as THREE from "three/webgpu";
import { texture as textureNode } from "three/tsl";

const makeSkiaMaterial = (gpuTexture: GPUTexture) => {
  const map = new THREE.ExternalTexture(gpuTexture);
  map.colorSpace = THREE.SRGBColorSpace;
  const material = new THREE.MeshBasicNodeMaterial();
  // The pixels are sRGB encoded in a non-sRGB texture format,
  // which three.js does not decode on its own: decode in the shader.
  // (@types/three declares ColorSpaceNode without its vec4 value type)
  material.colorNode = textureNode(map).colorSpaceToWorking(
    THREE.SRGBColorSpace
  ) as unknown as THREE.Node<"vec4">;
  return material;
};

On every frame, draw with Skia, flush the surface, then render the scene:

renderer.setAnimationLoop(() => {
  draw(); // draws with Skia and calls surface.flush()
  renderer.render(scene, camera);
  context.present();
});

In the example app, the cloth simulation runs in compute shaders, and the cloth is textured with a Skia drawing that is redrawn on every frame.

A three.js scene in a Skia canvas​

Three.js can also render offscreen, into a texture that a Skia canvas draws. The renderer expects a canvas context, so we give it a minimal stand-in whose getCurrentTexture() always returns the same texture, created on the shared device:

export const makeOffscreenTarget = (
  device: GPUDevice,
  width: number,
  height: number
) => {
  // three.js renders to the preferred canvas format when no render target is set
  const format = navigator.gpu.getPreferredCanvasFormat();
  const usage =
    GPUTextureUsage.RENDER_ATTACHMENT |
    GPUTextureUsage.TEXTURE_BINDING |
    GPUTextureUsage.COPY_SRC;
  const texture = device.createTexture({ size: [width, height], format, usage });
  // three.js reads the drawing buffer size from the canvas
  const canvas = { width, height } as unknown as HTMLCanvasElement;
  const context: GPUCanvasContext = {
    __brand: "GPUCanvasContext",
    canvas,
    // The texture is allocated up front on the shared device
    configure: () => undefined,
    unconfigure: () => undefined,
    getConfiguration: () => ({
      device,
      format,
      usage,
      viewFormats: [],
      colorSpace: "srgb",
      toneMapping: { mode: "standard" },
      alphaMode: "opaque",
    }),
    getCurrentTexture: () => texture,
  };
  return { device, context, texture };
};

After each render, wrap the texture into a new SkImage and publish it through a shared value:

const device = importDevice(Skia.getNativeDevice());
const target = makeOffscreenTarget(device, width, height);
const renderer = new THREE.WebGPURenderer({
  antialias: true,
  canvas: target.context.canvas,
  context: target.context,
  device,
});
// Initialize the backend up front so that the first published frame is a rendered one
await renderer.init();
renderer.setAnimationLoop(() => {
  renderer.render(scene, camera);
  const previous = image.value;
  image.value = Skia.Image.MakeFromGPUTexture(target.texture);
  previous?.dispose();
});

The shared value is then drawn like any other image:

<Canvas onLayout={onLayout} style={{ flex: 1 }}>
  <Image
    image={image}
    x={0}
    y={0}
    width={size.width}
    height={size.height}
    fit="fill"
  />
</Canvas>

The example app packages this recipe into a useThreeScene hook, used to render a glTF model inside a Skia canvas.

Lifetime rules​

Sharing a texture means sharing its lifetime. A few rules apply:

  • Use the shared device. Only textures created on importDevice(Skia.getNativeDevice()) can be shared.
  • Dispose Skia objects before destroying the texture. An SkImage or SkSurface wrapping a texture holds its own reference to it, so the texture stays valid even if the JavaScript GPUTexture is garbage collected. Calling texture.destroy() releases the GPU resource regardless of references: dispose the image or surface first.
  • Flush before sampling. After drawing into a texture with Skia, call surface.flush() before the WebGPU commands that sample it.
  • Adopt exported textures exactly once. The pointer returned by MakeGPUTextureFromImage() carries one reference, which adoptTexture() takes over.
  • Keep native buffers alive. An SkImage created with MakeFromNativeBuffer() samples the buffer in place: release the buffer only after the image is disposed.
